# 子代理书 · Subagentbook

MiMo CodeX 的 DSH 插件：同一逻辑子代理预设按实际供应商与模型选择Persona、工具和嵌套限制。根深度沿用DSH控制；工具组件由声明名单固定装配。

当前候选版本 `0.1.0-alpha.5`。`0.1.0-alpha.4`移除用户可配置的插件组合，仅按八件套工具声明固定装配官方组件。支持前台one-shot、后台持续会话和预设管理卡；持续实例可以接收后续消息、停止后继续，并在重启后恢复原模型、Persona、工具教学及深度上限。消息、后台所有权和父级完成通知复用DSH原生设施。恢复要求原代码、固定组件及权限仍可用，变化时明确拒绝。保存预设定义保持已有实例的快照，新实例使用新定义。预算和思考档位按精确目标模型校验，省略时采用目标模型默认；保存、发布和后续请求前重查能力，拒绝过期选值。

## 安装与检查

当前验证 DSH `0.2.0-rc.2` 与 `0.2.1-rc.5`，工作区开发基线仍为前者。Node >=22，npm 与 pnpm 11。

```bash
npm ci --legacy-peer-deps
npm ci --legacy-peer-deps --ignore-scripts
npx playwright install chromium # Linux CI: 加 --with-deps 安装浏览器系统依赖
DSH_RUNTIME_BIN=/absolute/path/to/dsh npm run ci
dsh plugin --profile <experimental-profile> add /absolute/path/to/dsh-subagentbook
```

使用匹配基线和独立 `DSH_HOME`。`DSH_RUNTIME_BIN` 可省略以使用 PATH 中的 dsh。共同 CI 执行编译与深度测试、真实宿主的离线会话测试、Playwright 浏览器回归、打包检查，以及本地目录/tarball 的官方安装门；不发送外部模型请求。浏览器门使用独立 DSH web profile、固定1280×720和离线适配器；从页面创建角色、校验标签、保存/刷新、制造版本冲突和服务端拒绝，并核对实际委派后的实例快照。失败保留截图、trace及脱敏服务日志；浏览器缺失会失败，不静默跳过。成功清理安装门目录，GUI现场位于输出的临时目录。可用 `npm run test:gui` 单独复跑。

安装后书默认为空。在插件详情页选择角色公共配置或精确供应商/模型变体，编辑后保存草稿。Persona/偏好文案支持直接文字或Promptbook引用；工具只声明名单，教学在Promptbook编辑。可委派角色与工具共用标签输入：ID按Enter确认，重复/未知项就地提示，×整项移除，确认后仍需保存。插件自动注册八件套的`tool.<name>`及纯Bash的`tool.bash.only`，按模型解析并保存会话快照；未本地化保留实际原生描述。预算使用滑块与精确数字，思考使用模型公开的命名档位；小加号可加入按API文档点分路径配置的数字/文字/布尔请求参数，数字可自设滑块范围，无需手写JSON或转换请求对象。编译预览按当前配置镜像解析，不发模型请求。配置方式、旧插件/教学迁移、示例与服务API见 [配置文档](docs/configuration.md)。书实例要求宿主提供llm-mimo和`autoInject:false`的Promptbook，缺失拒绝创建/继续。宿主其他全局上下文插件仍由profile管理。

### 内置开发 + UR 专家团

在标题栏点击“专家团模板”，选择一个已配置的初始供应商/模型，点击“添加整团”，检查关系图后保存草稿。十个角色的 Persona、工具、权限、派遣关系和子级深度一起加入，无须手工逐个配置：开发者 → UR 跑者 → 主审与三视角、独立核验，另有疑难专家、文档审查和只读中继。完整团队需 DSH 原生子代理深度至少 3；模板不会替你改宿主限制或发起模型任务。

这是 [UR 团队候选](examples/ur-team.json) 的可编辑副本，已在 MiMo V2.6 Pro 实战，其他模型的效果需单独验证；以后可按角色添加或修改精确模型变体。模板不携带 API Key、输出预算或私有思考档位。每次添加使用独立的 `ur.*`、`ur-2.*` 等角色 ID 并同步内部委派边，不覆盖旧角色或已有草稿。普通会话默认只获委派开发者的入口；原生预设菜单仍沿用现有各角色直接选择能力（验证副本除外）。使用开发者作为团队根，模型继续用 DSH 原有选择器。保存不改变旧会话快照。

标题行的角色名展开关系图，用节点选择角色并收起进入配置；悬停查看工具、权限和深度。图可切换公共配置或精确供应商/模型；缺该路由的角色以虚线边框标识，点击进入其公共配置。循环节点/边标为琥珀色，标题警告可打开全部配置的“可能关系”并集，帮助发现跨模型潜在循环；展开警告中的角色可定位委派字段。循环允许保存，实际执行沿用祖先深度等限制。图显示已确认的当前草稿，不表示运行中实例或实际深度；跳转保留未保存输入和保存校验。

标题“＋”和角色信息中的“新增模型变体”都在按钮旁打开表单，自动聚焦并就地提示错误。新增角色确认后定位到关系图中的新节点，显示“已添加”；仍需保存草稿。取消、Escape或点击外部关闭浮层并保留未提交输入；模型菜单先关闭再关闭浮层。新增角色不会自动成为当前角色的可委派项。

浏览器回归同时覆盖两个模型的工具/预算覆盖、恢复公共配置、跨作用域无效输入的保存阻止，以及请求字段类型/范围/值的刷新保留；见14号计划（本地验证记录）。这些是配置与交互验证，不代表模型效果结论。

书内角色也会出现在 DSH 原生预设菜单中：先选角色，再用原有模型选择器选它支持的模型，发送第一条消息。首次实际装配才冻结该模型的 Persona、工具、权限、预算及请求参数；不支持的模型会拒绝请求，修正选择后可再试。已有根会话固定模型，续聊和重启沿用原快照。根深度为 0，限制仍由 DSH 控制；角色自身的嵌套深度仅在它作为子级时生效。删除角色后保留标为“历史会话”的恢复入口，不能用来新建已删除角色。原生 fork 暂不支持，明确拒绝。验收见15号计划（本地验证记录）。

审查者需要独立构建/测试时，将“文件权限”选为“独立验证副本”，由可写跑者直接委派。它在独立Git副本中写构建产物，原树保留只读；实例面板可展开“验证来源”，核对来源是否仍一致、副本输入是否修改。原树修复后新建验证实例，旧副本不自动更新或回写。支持范围、缓存和留档见[验证副本契约](docs/verification-workspaces.md)。

[首批角色候选书](docs/role-candidates.md)提供模型自行撰写的研究规划、施工、核对审查Persona，以及按模型选择的工具声明和生成证据。它供按需装入，不自动覆盖现有书；候选组合及小任务验收不代表通用最优预设。

## 开发与验证

一次性任务的实例面板可[导出完整报告](docs/report-export.md)，保留宿主原文及实例/角色/模型/权限来源。源码仓库的 `npm run report:export -- <DSH_HOME> <sessionId> <new-directory>` 可直接保存原文和校验清单，避免让模型手抄长报告。

修改前读 [AGENTS](AGENTS.md)，当前非 GUI 接力入口为 3 号计划 handover（本地验证记录），GUI 见 2 号计划（本地验证记录），持续会话见 1 号计划（本地验证记录），前台 alpha 见 0 号计划（本地验证记录）。GUI 复用宿主现有设施并参考 Promptbook，面向桌面键鼠，不支持触屏。

Client 源码在 `src/client/`；书解析/配置解析共用 `lib/definition.js`。改后运行 `npm run build:client`，不要手改生成的 `lib/client.js`；CI 检查产物一致性。`npm run preview:gui` 创建无凭据的独立 web 预览，安装相邻工作区插件，供界面验收；它不运行模型任务。

付费的本地最小验收使用 `npm run preview -- --provider-snapshot <private-provider.json>`；该快照格式为 `{id, config, key}`，仅把 key 放入启动进程环境，不写进 profile 或报告。脚本新建临时 web profile、安装相邻工作区插件并运行两个小任务；可重复，但不进入 CI。结束预览时 Ctrl+C。持续验收添加 `--continuation`；验证一个小任务、后续消息与服务重启后续写。测试产物保留在相应计划被忽略的 `local-artifacts` 目录。

三角色小功能验收使用 `node scripts/pipeline-acceptance.mjs --provider-snapshot <private-provider.json>`，每角色期限 10 分钟，最多一轮修复并复审。若规划/施工已完成且独立检查通过，可显式加 `--resume-review <archived-run-directory>`，在新临时 profile 校验原源码哈希后只续接审查；它不恢复旧 one-shot 实例，不自动重跑。

若后续人工复核得到明确缺陷，可以在接续命令上加 `--repair-findings <verified-findings.json>`，安排一次有限施工与差异复审。文件包含非空 `findings` 数组，必须由可信调用者核对；模型的 `pass` 不能代替需求和实际测试证据。原始项目与审查不覆盖，修复另存新产物。

书内根会话与子会话顶部的“实例配置”读取创建时冻结的角色、模型、工具、权限、深度与Persona。设置后来改变会单独提示；它不会把新设置当成旧实例的实际配置，也不执行恢复、写入或模型请求。保存拒绝保留原生错误及草稿；版本冲突必须撤销/重新应用，不能用重试静默覆盖另一窗口。

实例诊断将跨宿主加载的未结算运行标为中断；一次性任务另显示最终报告是否完整保存（空结果单独标识），不可读取时禁用导出。检查状态不会自动重跑任务；原生宿主的完成标签不代表报告可用或验收通过。

[阶段存档与接续](docs/recovery.md)：实例面板可导出最近阶段记录，并按需准备、复制接续任务。草稿不含思考正文或工具原始结果，也不替代最终报告；复制不会自动发起任务。


One-shot结果提供有界的最终答复首段与 `report.nextOffset`。父级通过 `subagentbook_result` 分页取回完整交付文本；原始思考保留子会话，结果持久存于DSH_HOME且仅原直接父级可读，详见[配置契约](docs/configuration.md#one-shot-delivery-and-paged-results)。验证管理目录由内部忽略规则排除出项目Git/改动卡，仍保留恢复证据。

### rc.5 一次性任务界面

候选版通过公共客户端槽位与已认证实例诊断，把书内一次性任务标为“一次性”，并显示只读记录提示。打开记录仍使用宿主真实地址；不改写持久 descriptor/catalog，也不授予续写权限。持续任务保留原生输入与继续行为。代码升级不会自动迁移已有冻结实例。

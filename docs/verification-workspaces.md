# 独立验证副本

将角色的“文件权限”设为“独立验证副本”（`actionScope: verification-copy`），由可写跑者直接委派。角色继续自行选择工具、模型与Persona；本能力不新增模型工具，也不替代测试计划。典型链路为跑者组织只读主审/三视角，再直接调用验证角色执行独立测试。

## 权限与生命周期

仅接受父级有效文件策略为workspace-write或danger-full-access的委派。子级cwd及原生可写根收窄到父工作区内 `.subagentbook-verification/<instanceId>/workspace`，审批固定never。原树、管理清单及其他副本不在子级可写根内，仍可读取。创建过程也使用原生完整沙箱，避免宿主文件复制/Git操作成为绕过原权限的通道。没有原生文件策略、受约束Bash或完整沙箱时拒绝，不降级。

只读主审不能通过此模式给下级新增写权限；请由可写跑者直接委派。全为验证副本的角色不进入根预设菜单；混合变体的根入口也拒绝验证副本路由。验证角色的下级继续服从其实际副本边界与既有深度限制，不能重新获得原树写权限。

前台及后台持续模式均支持。首次发布前重查来源、父权限和角色/模型能力。恢复保留原副本、模型/文案/工具、父子关系、深度与输入指纹；副本或清单缺失、清单篡改、父撤权、代码变化均拒绝。旧副本的源树后来变化不自动覆盖它，适合继续核对原轮；要验修复后的代码须新建实例。取消或发布失败回滚未使用副本；已发布副本保留，不随会话结束删除。

## 输入契约

V1要求会话cwd为Git仓库根且已有HEAD，当前在Linux原生执行器验收。输入为Git跟踪文件及未忽略的新文件的实际工作树内容，保留未提交修改/删除和普通权限位。不复制源暂存区状态：副本有独立浅克隆的HEAD基线与自己的index，当前修改表现为相对该基线的工作树差异。原index不变。

不复制忽略文件/缓存、源Git config、钩子、远程配置或alternates；Git对象通过非local传输独立复制，无源对象硬链接。副本禁用Git hooks。完整历史、其他分支、忽略的本地记忆/素材及已编译库不属于输入；必要时可以只读查看原树，测试依赖应在副本构建。若任务依赖这些材料，须显式纳入后续验收准备，不能假定完整机器已复制。

符号链接、包含符号链接祖先的输入、submodule等非普通文件明确拒绝；非UTF-8路径、超20,000文件或256MiB输入拒绝。管理目录为插件专属，已有同名外部目录不接管。源树位于 `/tmp` 或平台临时可写根时拒绝，因为原生workspace-write本来允许这些位置写入，不能承诺保护源树。临时测试/工作副本须放到其他位置。

## 构建环境与结果

验证角色的原生Bash以副本内 `.verification-cache` 承载XDG、Gradle、.NET/NuGet、npm、Go、Cargo、pip/uv缓存，Cargo target也位于副本。单个绝对环境路径若指向原树内部，将映射到副本对应位置；例如宿主设置的engine DLL路径不会继续指向原树旧产物。PATH等路径列表不重写；自定义复杂环境和外部依赖仍须任务明确处理。其他角色的环境不变。没有复制缓存不等于无需restore或下载。

模型运行上下文提供原树、副本、清单路径及输入指纹；原生工具仍执行其权限约束。模型应报告实际测试命令、工作目录、产物路径和退出结果；构建引用也须核对，不能仅因某个DLL存在或旧日志成功就认定已验证。

创建清单保存原HEAD、逐文件内容/权限、文件数、大小与时间；清单位于副本可写根外，并由实例记录固定哈希。前台工具结果附带宿主计算的验证来源；根/子实例面板中的“验证来源”按检查时刻比较当前原树与原输入，另列副本原输入文件是否改动。构建输出不属于原输入。“来源一致”仅证明输入归属，不证明命令运行或测试通过；后台完成通知也不能替代查看实际证据。

验证性修改只发生于副本，不自动回写。跑者核实意见后在原树修复，再委派新验证实例。封存时保留清单、原始模型输出、测试命令与日志；构建缓存/中间产物可在证据保全后清理，但删除原副本会让旧会话不能恢复。本插件当前不自动做缓存回收或归档。


## Git与交付差异

插件在自己拥有的 `.subagentbook-verification/` 内写入固定 `.gitignore`（忽略该目录下全部内容，包括忽略文件自身），使manifest、owner和内嵌Git副本不进入原树的Git状态与宿主改动卡。项目根 `.gitignore`、源Git配置/info-exclude和原index不因此改动。目录仍保留用于来源核对与恢复，不自动删除。

同名外部目录、未知忽略内容或已经被Git跟踪的管理路径均拒绝创建，不能通过覆盖用户文件来隐藏问题。旧版由插件创建的目录在下一次授权创建验证实例时补齐内部忽略规则；被封存的旧运行不会仅因查看而修改。多个验证者首次同时创建时共享受控标记，各自使用独立实例目录。

父级委派时直接使用实例上下文提供的验证工作区。不要给核验者要求在原树里自建 `build/...` 副本的旧配方；它对原树没有写权限。
